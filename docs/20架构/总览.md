# 架构与模块边界

范围为需求阶段的模块职责和技术决策边界。当前只有文档，没有前后端、接口、数据库、外部模型配置或运行服务；不存在可据源码描述的实际调用链和数据表。

产品规则以[产品总览](../10产品/总览.md)为准。下述模块划分是建议方案，待实施范围确认后细化。

## 1. 目标与约束

支持当前学习语言与双语显示，把场景、资料和个人输出连接起来；语言变化不能破坏作品归属，辅助内容不能覆盖用户原意。

为英语优先、德语扩展留出语言边界。界面文案、学习内容、用户作品和参考链接的语言归属需要明确，不能靠改页面标题模拟多语言。

## 2. 建议模块职责

| 模块 | 负责 | 依赖 |
| --- | --- | --- |
| 语言与显示偏好 | 当前语言、双语开关和中文辅助呈现 | 语言资源 |
| 场景学习 | 生活、商务和技术情境及表达练习 | 语言偏好、学习内容、资料 |
| 观点表达 | 原始想法、结构整理、外语候选和用户定稿 | 语言偏好、表达材料；可选语言辅助服务 |
| 视频稿准备 | 将选定作品整理为口述稿 | 观点作品 |
| 资料与表达库 | 来源链接、可复用表达和作品检索 | 内容及作品归属 |
| 保存能力 | 保存偏好、输入和用户选择结果 | 待定存储方式 |
| 可选语言辅助 | 改写、朗读或识别等能力 | 待确认外部服务及授权 |

## 3. 依赖方向与关键机制

场景练习和观点表达共享语言偏好及表达材料。视频稿准备以用户选定的作品为输入；参考资料可以附着于任务，不能替代用户内容。

建议将展示语言与内容语言分开建模：切换显示不能篡改作品语言；原始中文想法与目标语言表达存在关联，但保持各自内容。此处描述业务概念，不指定数据库字段、表名或接口结构。

辅助生成结果建议作为候选交给用户选择。若引入 AI，需区分原稿、候选和已选内容；调用失败、超时或取消保留输入，不自动重试并覆盖正式作品。使用外部能力前明确服务对象、发送内容、费用和权限。

## 4. 数据与存储现状

尚无实际存储或 schema。本次不创建数据库、数据字典、迁移和空表设计。预期需要保存的业务对象包括语言偏好、学习材料、原始想法、用户选定作品及参考链接；是否保存录音和练习记录仍待确认。

浏览器本地保存、文件保存或服务端持久化应依据使用设备、数据量和备份要求选择。个人使用不等于已授权公开托管，也不自动需要账号体系。

## 5. 质量目标及边界

- 切换语言与双语显示后，内容归属和用户输入保持正确。
- 错误、空内容和参考链接受限状态可理解，失败不吞掉用户稿件。
- 后续界面应支持清晰阅读、键盘操作和表单标识；设备范围及响应式验收需确认。
- 正式作品与辅助候选的区分可见；保存、录制和发布结果分别说明。
- 模型或语音能力未接入时如实呈现，不用模拟响应冒充真实能力。

没有已批准的并发规模、延迟、可用率或学习效果数值，不编造指标。

## 6. 待定技术决策

技术栈、运行时版本、页面路由、API、数据存储、账号权限、AI 服务、语音服务和部署方式均未确定。进入实施时先核现有工具和项目要求，复用环境与缓存，不为文档安装依赖或启动服务。
