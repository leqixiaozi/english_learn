# 建设范围与阶段建议

本次已授权结果为：使用个人 skills 生成项目文档，commit 并 push 到现有仓库当前分支。该指令不授权网站编码、外部服务调用、音视频操作或部署。

产品目标见[产品总览](../10产品/总览.md)，技术边界见[架构总览](../20架构/总览.md)。本文件只维护建设顺序与启动条件，不记录日常进度。

## 1. 本次交付物与依据

建立项目读取入口和本机个人技能映射，将定位、用户要求、语言显示、表达思维训练、观点到视频稿的流程，以及待定项整理为当前正文。建立架构边界和维护规范，便于后续讨论及实施。

文档应使其他开发者能够区分已明确要求和设计建议，不能把待定技术选择或用户水平写成事实。

## 2. 建议建设顺序，待确认

| 建议阶段 | 目标与交付成果 | 启动依赖 |
| --- | --- | --- |
| 英语最小闭环 | 从一个生活或工作场景进入练习，完成自己的表达并保存；目标语言与双语显示可切换 | 确认水平、首批场景、使用方式及技术方案 |
| 观点与视频稿 | 中文观点组织、外语表达、用户定稿、口述稿准备相互衔接 | 最小闭环的内容和保存能力；确认视频主题与格式 |
| 德语内容扩展 | 提供适合当前水平的德语场景与表达任务，保留独立成果 | 确认德语水平及建设范围 |
| 可选语音或 AI | 在既有流程中加入需要的陪练、改写、朗读或识别 | 用户确认能力、服务、费用与数据发送边界 |

推荐先让用户完成一次有用表达，再扩大内容和辅助能力。多语言边界从设计开始保留，德语内容的上线顺序并未批准；若用户需要首版同步支持，应调整上述阶段。

视频目标先明确内容准备与实际录制的边界。自动剪辑、成片和发布不包含在上述建议阶段，不能因“视频输出”自动扩大范围。

## 3. 保持项与前置条件

实施须保持现有检出及当前分支，保护其他任务改动；先确认阶段范围，再核工具及依赖。不因生成文档而安装框架、创建数据库或调用模型。

启动编码前集中确认：英语与德语水平、主要场景、首版德语范围、视频产物形式、是否需要 AI 或语音，以及使用环境和保存方式。具体未决项在产品总览维护，本处不复制答案。

## 4. 交付与进入下一阶段的依据

本次交付依据是文档已覆盖用户要求、索引与链接有效、未将建议冒充决定、暂存文件属于本任务，且提交已到达目标远端分支。它不包含任何网站运行或业务验收。

后续阶段以获确认的产品目标和可观察结果为依据，按相应阶段运行实际验证。文件数量、页面外观或 HTTP 成功不能替代“用户能够完成表达任务”的业务成果。
