# 中文表述到英文语法

## 定位

这是用户明确要求的独立核心专项：用本人想说的中文，学习怎样搭建英文句子；从基本词句开始，为高频场景服务。整体范围见[产品总览](总览.md)，课程组织见[场景教学与专项训练](课程与练习规划.md)。下文为建议训练方式，不宣称已经实现或经实验证明最快。

不建立另一本从头背到尾的语法大全，不另设词汇背诵。中文用于明确意思和暴露当前结构卡点，随后逐步减少完整译文提示，最终能直接用英语回应场景。无需把每句话都先想成中文才能开口。

专项绑定贯穿项目中的真实表达意图：先确认用户在当前剧情想说什么，再教完成这句话所需的结构，随后回到同一人物、任务与项目成果。可以独立进入查看，但不随机提供与当前故事无关的中译英题库。

## 1. 一次只解决自己要表达的意思

建议流程：输入自己的中文 → 确认意思和语境 → 拆出“谁、做什么、什么时候、对谁／什么” → 自己尝试搭英文 → 按需查看最小提示和参考表达 → 解释当前用到的语法 → 改一个条件再说 → 回到实际场景。

例如“我改了接口”未说明具体时间，也未说明是在讲过去经过还是强调现在已经可用。不能仅凭“了”就机械判断时态；有影响时先问清语境，或分别说明两个表达的适用场合。不能替用户补出没有说过的原因、时间或立场。

中文输入属于用户主动编辑内容；即使普通学习页未开启双语，也可以显示本人输入。额外中文讲解按双语／显式帮助设置显示，不让专项强制覆盖全站语言偏好。

## 2. 基础起步示例

以下为人为编写的教学示例，不是用户已经说过的话或模型结果。

中文：**我现在正在检查这个问题。**

先明确意思：我＝执行者；检查＝动作；这个问题＝对象；现在正在＝进行中。参考英文：

> I’m checking the issue now.

显示结构：**I｜am checking｜the issue｜now**。本次重点是“正在做”如何表达，解释 am 与 checking 在这个句子中的作用；the issue 作为当前问题整体理解，不展开一整章冠词和名词规则。

然后让用户自己改：

| 改变的意思 | 参考表达 | 按需学习的点 |
| --- | --- | --- |
| 我每天检查日志 | I check the logs every day. | 经常做的事；不沿用 am checking 表示日常习惯 |
| 我昨天检查了日志 | I checked the logs yesterday. | 明确过去时间；动作形式变化 |
| 我现在没有检查这个问题 | I’m not checking the issue now. | 当前句型的否定 |
| 你现在在检查这个问题吗？ | Are you checking the issue now? | 当前句型怎样提问 |

这些变式按进度逐个使用，不在第一课一次灌入全部时态。先让用户知道“意思变了，英文哪里需要变”，再逐步掌握形式；不把中文词序与英文单词进行逐字连线。

## 3. 专项的最小递进路径

| 顺序建议 | 解决的高频表达问题 | 返回的场景 |
| --- | --- | --- |
| 谁／什么＋状态或动作 | 我是谁、在做什么、需要什么；区分必要的 be 与动作动词 | 说明当前工作、点餐 |
| 否定与提问 | 我不能做、我不明白、你是不是这个意思 | 确认需求、请求帮助 |
| 时间与动作形式 | 正在做、经常做、明确过去、下一步计划，按需逐项引入 | 进度、约时间 |
| 连接简单意思 | 给原因、补一个例子、说一个简单看法 | 问题说明、个人观点 |

这是围绕起步任务的路径建议，不是已批准的完整英语语法范围。复杂从句、所有时态和学术写作不作为基础阶段的前置条件。

### 3.1 从已核读的任务确定本次语法

以下是据素材沟通结构为 Relay **原创的短句示例**，不是原视频逐字句，也不是本人已确认的履历或承诺。来源事件见[Easy English 完整事件提炼](10学习资料/EasyEnglish课程目录.md#7-从字幕提炼的完整事件)。

| 当前想说的中文 | 先完成的英文意思 | 当前需要理解的结构 | 回到任务的实际结果 |
| --- | --- | --- | --- |
| 我负责后台，今天在修登录 | I work on the backend. I’m fixing a login issue today. | 日常职责与此刻动作分成两句；不把所有动词都接在 be 后 | 对方理解自己的职责和本次进展，S007／S152 |
| 你说的是周五下午三点吗 | Do you mean Friday at three? | 先用一个可核对的问题；时间和语气清楚比复杂礼貌更重要 | 对方确认或纠正，随后写进日程，S094 |
| 我需要多一天，因为测试还没完成 | I need one more day. The tests aren’t finished yet. | 先独立表达需要及状态，再按能力用 because 连接；不要只由中文“没”猜时态 | 商量剩余工作、影响和新安排，S153；句子本身不构成新的交付承诺 |
| 这个问题还在，我已经重启过了 | The issue is still there. I restarted the app. | 当前状态与已做动作分开；有明确过去时间时再加上去，不强求一次学完完成时 | 对方不重复安排同一步，并提出下一项检查，S179／S181 |
| 我们能先做核心功能，把附件留到下一版吗 | Can we build the core features first and add attachments later? | can 请求讨论、first／later 表顺序；先说清取舍对象 | Maya 回应并记录范围，而不是只做一句翻译，S114／S169 |
| 我订了房，想核对一下入住日期 | I have a booking. Can I check the dates? | 中文“订了”可先表达当前已有预订的状态，不机械强制过去时 | 用同一预订确认日期，再继续入住，S217／S235 |

新增系列正文的任务参考见[SR 机制目录](10学习资料/系列课程目录.md#7-提炼给-relay-的79组任务机制)。以下也是本站原创迁移示例，首次先用左侧的短句主干，语法复杂度由实际需要决定：

| 本人当前想说的话 | 可先说出的短句 | 借任务澄清的语法／意思 | 必须返回的互动 |
| --- | --- | --- | --- |
| 我现在不方便，下午可以吗 | I’m busy now. Can we talk this afternoon? | 状态句加请求，不需要先学复杂委婉结构；VOA忙闲只作机制参考 | 对方给出或接受时间，S155／S325 |
| 文档写周一，你说的是周二，哪个才对 | The document says Monday. You said Tuesday. Which is correct? | 来源和已说的话分句；初级不强求间接引语和时态后移 | 找到决定依据并更新有效资料，S133 |
| 我试过了，但问题还在 | I tried that. The issue is still there. | 已做动作与当前状态分开；“试过”不自动等于解决 | 对方提出下一检查，S179／S196 |
| 我觉得可能是配置，但还没确认 | It may be a configuration issue. I’m not sure yet. | 起步也可先说 I’m not sure，再加猜测；may 不等于事实 | 提出怎样检查，随后按证据改写，S183／S299 |
| 我同意这一点，但我们的时间更紧 | I agree with that point. But we have less time. | 承认部分理由并给当前约束；不把所有不同意见说成对方错误 | 商量范围或保留条件性判断，S153／S346 |

一次只处理一个本人卡点；不是把六行合成一堂语法课。练完换一个对象或时间，在没有中文题干和完整译文时回应角色的下一问。日期、时间、否定和数字的核对贯穿故事，也服务于后面的字幕与视频彩排。

### 3.2 从新核读的完整来回处理中文表达卡点

来源是[SR35—SR79](10学习资料/系列课程目录.md#7-提炼给-relay-的79组任务机制)。下面是为本站自编的候选表达，不是原稿摘抄，也不是本人履历。先解决当前想表达的意思，再补结构；只在出现相应卡点时选用，不成为新一套必背句。

| 本人中文意图 | 可先使用的表达 | 先弄清什么 | 回到哪件事 |
| --- | --- | --- | --- |
| 我很想申请这份工作，但想不起“有动力”这个词 | I want this job. I like solving problems with a team. | 先解释真正的动机，不等想起一个形容词才回答；理由仍需符合本人事实 | S034继续回应追问 |
| 我负责接口；我在测这个改动；以前我做过一个项目 | I work on APIs. I’m testing this change. I worked on a project before. | 日常职责、此刻动作与过去经历有不同结构；“正在测试”不是“已经通过” | S030／S170，起步一次只处理其中一项 |
| 是让我做午饭，还是一起出去吃 | Do you mean lunch at a café? | 先用可回答的短问题核意思，熟练后再扩展完整两个选项；不是逐字对译do lunch | S097确认具体安排 |
| 这是团队做的，我只负责其中的接口 | Our team built it. I worked on the APIs. | we和I各指谁、动作发生在何时；团队成果和个人行动分句 | S043澄清贡献 |
| 谢谢邀请，但我今晚不能参加 | Thank you for inviting me. I can’t join you tonight. | 感谢和拒绝都说清即可，不必先学长委婉句，也不捏造公司规定 | S260完成回应 |
| 昨天我们试了一个办法，现在问题仍在 | We tried one approach yesterday. The issue is still there. | 过去动作与当前状态分句；先后叙述不自动要求过去完成时 | S049讲经历，S179继续调查 |

本次新增SR54—SR79还可按以下实际卡点择用，全部为本站原创候选，不是来源台词或本人已经发生的事实：

| 当前中文意图 | 起步可说 | 按意思选择结构 | 回原任务检验什么 |
| --- | --- | --- | --- |
| 你是负责这一步的人吗 | Do you handle this step? | 先核职责，不把“是”逐字套成be；handle难时可用Do you do this?并指出任务 | S110找对实际处理人 |
| 是周二还是周四？几点，哪个时区 | Tuesday or Thursday? What time? Which time zone? | 初次可用短问句，不先要求复杂间接问句；核一次会议还是两个日期 | S094／S286核同一日程 |
| 我重启了，但还是打不开文件 | I restarted it. I still can’t open the file. | 过去尝试与当前不能分两句；不必先会现在完成时才能求助 | S179记录已试且无效 |
| 是参数不对，还是我理解错了 | Is this the right value? Did I understand this correctly? | 先把对象和值核清，不把不懂当成已确认的代码缺陷 | S148／S156继续同一调用 |
| 我们只是在同事之间试过，还没问用户 | We tried it with a coworker. We haven’t asked the user yet. | 先能说We still need to ask the user；需要表达截至现在未做时再引入haven’t＋过去分词 | S300补真实用户反馈 |
| 他答应帮忙，但时间还没定 | He said he can help. We still need to set a time. | 转述承诺与未完成动作分句；不把“答应了”改成已经做完 | S155确认后续安排 |
| 我同意先试，不是已经决定全面采用 | Let’s try it with a small group first. We haven’t made a final decision. | first标范围和顺序，后句需要时再用；同意试用的对象应说完整 | S309／S310核试行及判据 |
| 这是我的猜测，我还需要检查 | This is my guess. I need to check it. | 不会推测情态动词也可先说清不确定；熟练后再用might等表达可能 | S182／S340分事实和判断 |
| 这个做完了，那项下个月才做 | This part is done. We plan to do that next month. | 当前完成状态与未来计划分开；避免把所有“了”都讲成已经完成成果 | S331／S342用记录支撑 |

来源中的will、would、条件句与反身代词讲解有简化，不能抽成所有情境的绝对规则。后续教材先核具体语境、动词含义和时间关系，再按当前需要解释；听者能否理解和本人能否独立回述仍需实际练习观察。

遇到“了／过／一直”先问：说的是过去某次动作、当前状态、持续过程，还是经验；不能按一个中文字机械选择英文时态。持续形式与完成形式不能统称“都已做完”。同样，because后可接完整原因句，since 8 a.m.这样的时间短语本身不是完整从句。来源讲解被简化时，应按本次句子讲清意思和结构，不照抄成通用规则。

### 3.3 用参考专题补当前想说的话

[语言工具箱与系列排序](课程与练习规划.md#26-原创主课与参考专题的系列排序)服务于当前意图，不要求先看完语法片。Easy English新核读中，stop doing／to do、used to／be used to和持续尝试可提供语境；以下是面向本人任务的原创示例，不是引用原片或已经发生的事实。

| 本人中文意图 | 可以先说 | 当前要分清什么 |
| --- | --- | --- |
| 等我想一下，我想把意思说清楚 | Give me a moment, please. | 先争取时间，再用简单句解释；不用填满所有停顿或强行加习语 |
| 我暂停手头的事去查日志；我不再查日志了 | I stopped to check the logs. / I stopped checking the logs. | 前者说停下来做另一件事，后者说停止某动作；先问清中文到底要表达哪个意思 |
| 我以前远程工作；现在习惯办公室工作 | I used to work from home. / I’m used to working in an office. | 过去习惯和现在已适应分开，不能只看中文的“习惯”选结构 |
| 我又试过，仍不行；我一直在尝试但还没掌握 | I tried again. It still doesn’t work. | 起步用过去动作加当前状态即可；需要强调持续时再补完成进行形式，不由视频标题决定进阶 |

本批参考补充以下意图。先用最短而清楚的表达办事，需要强调时间关系时再扩展；例句是原创任务示例，未声称Relay发生过这些事实。

| 本人中文意图 | 可以先说 | 按需扩展与回到任务 |
| --- | --- | --- |
| 我每天检查；我现在正在检查 | I check it every day. / I’m checking it now. | 先用时间线区分习惯与此刻动作，再给S007或S182一个真实语境 |
| 已改了，想请你按原步骤再试 | We changed the code. Please try the same steps again. | changed说明已采取动作；It works in this test.只说明本次观察，不自动代表所有流程通过，回S299核结果 |
| 我建议减范围；期限必须先确认 | We could reduce the scope. / We must confirm the deadline first. | 分清选项与明确要求；could/may/might不是一张固定概率表，回S169取得决定 |
| 要几张票？还有多少时间？ | How many tickets do we need? / How much time do we have? | 可数项与时间量结合当前票务/日程；只取本次需要的词，不背包装单位全表 |
| 我先改了设置，后来测试失败 | I changed the setting. Then the test failed. | 初步先交代两步；需强调过去之前时可说“I had changed the setting before the test failed.”，时间先后不直接证明因果 |

被动语态、过去完成与将来进行类视频留在工具箱后段；先用“谁做了什么—现在观察到什么—下一步谁来做”也能清楚交流。字幕中的hand/had、didn't used to等错识不作为语法答案；在未经校对前不让自动稿决定反馈规则。

原片“母语者不用very good”或“更强形容词一定更流利”等概括不采纳；简短、正确、适合听众的表达可以保留。字幕里gonna、字母和语法公式有错识别时，先核原音或可靠文字，不把自动稿直接当参考答案。

本轮核读还可补两个即时表达卡点，均为本站原创候选句，不是来源原文或新增必修：

| 当前中文意图 | 起步可说 | 借当前任务弄清什么 | 回到互动 |
| --- | --- | --- | --- |
| 我只听到了“周末”，其余没听清 | I heard “weekend”. Could you say the rest again? | 把已听到和未听到的部分分开，不一律说全部不懂；heard是一次过去接收，could用于请求 | 参考EV63；仍断续就约回拨并标具体时间待定，不假装已经恢复 |
| 我先做计划，再做实际工作 | Let’s make a plan first. Then we can do the work. | 中文“做”按当前对象选择搭配，不背“make创造、do活动”的绝对规则；由3TnrxOJ1bjY的make/do语境启发 | 回S139／S153核计划内容、分工和下一步，不以学会两个动词代替工作推进 |

## 4. 交互建议

页面主体展示自己的中文原文、英文尝试与当前必要操作。按已确认的[全站展示原则](总览.md#61-已确认的首页与全站展示原则)，禁止引导性内容；意图拆解、结构说明、语法、例句、参考表达及反馈全部放在页面最下面并默认折叠，主动查阅或检查后再展开对应小节，不常驻侧栏或输入框附近。原文和尝试保留，候选不能自动覆盖已选表达。

起步可用填少量关键位置；稍后撤去句子骨架，改用关键词或英文情境提示，最后在没有中文题干和完整参考句时回应。能抄写不等于能独立写，能读出译文不等于能自己说；反馈分别说明。

纠正先看是否保留原意、能否理解，再优先处理当前学习点。语法正确但不适合语境，与语法错误分开解释；允许多个自然答案，不能按参考句字符串一致性判错。用户决定是否采用候选改写，不能自动覆盖原稿或正式作品。

## 5. 怎样判断有帮助

建议观察：能否说明为什么这样组成句子；能否改变人物、时间或否定／疑问后正确表达；能否在另一高频任务里脱离完整译文说或写；隔一段时间是否仍能用。具体评分和间隔尚未确认。

欧洲委员会关于[多语言意义中介](https://www.coe.int/en/web/common-european-framework-reference-languages/mediation)的说明支持将已有语言资源用于理解和表达。本专项由此采用中文作起步支架；这不证明逐句中译英是学习听说读写的最快方法。专项必须回到英语听读、独立输出和真实互动，以实际使用效果调整提示强度。
