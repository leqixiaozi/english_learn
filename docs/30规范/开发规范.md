# 开发与文档规范

适用于当前资料维护和后续获授权的开发任务。现阶段无源码或构建配置，本文件不预设框架、包管理器、测试工具或代码目录。

## 1. 需求与授权

- [产品总览](../10产品/总览.md)区分用户明确需求和待确认建议；建议不能作为已批准的实施契约。
- 按最新用户指令核任务范围。落文档、commit、push、编码、运行、外部模型调用和部署分别核已有授权。
- 本次范围为文档生成与 Git 交付。后续实施依据见[建设规划](../40规划/建设规划.md)。

## 2. 文档维护

- 个人开发流程及文档治理为方法入口，路径从根目录的 `AGENTS.local.md` 取得。
- 共享资料使用 Markdown 与仓库内相对链接。新分类目录使用两位数字直接连接中文名称，按需展开，不创建空模板。
- 同一主题维护一份当前正文，历史交 Git。README 是索引，不能重复正文、记录讨论流水或堆叠完成清单。
- 分开陈述需求目标、建议方案、实际实现和验证证据。未读取的外部资料不能标为已核实，未运行的检查不能标为通过。
- 本机映射、凭据、缓存和索引不进入共享历史；不复制独立知识库或个人技能正文。

## 3. 后续实现需保持的边界

- 遵守产品语言规则；双语开关影响展示，不能修改用户作品或改变练习归属。
- 个人内容保留原意；外部或辅助生成内容须可识别，采用前保留候选状态。
- 涉及输入和保存的流程须明确空、错误、取消及未保存状态，失败保留内容。
- 视频稿、录制、成片、发布分别表达实际状态；缺少能力时不能显示成功。
- 外部调用只发送任务所需内容，记录及错误提示不泄露凭据。
- 不凭文档擅自引入技术栈、依赖、模型、存储或业务数据操作；实现前依据确认范围细化。

## 4. 工作区与 Git

默认使用现有检出及当前分支。未明确授权时不创建或切换分支、worktree；提交前核未提交改动与归属，不覆盖或夹带其他任务内容，不改写历史。

按任务显式暂存文件。文档交付核目录、需求覆盖、链接、敏感信息和 `git diff --check`；获准推送后核本地 HEAD 与目标远端分支一致。推送结果不代表网站已实现或验收通过。

## 5. 验证口径

当前文档没有构建与业务测试，验证限于文本、链接、需求覆盖和 Git。后续代码检查按个人流程及实施范围确定，源码检查、构建、页面渲染、接口健康和真实业务验收分别报告。

没有 `.codegraph/` 时不自行建立索引；有索引时理解代码先使用 CodeGraph，并核关键结论与当前源码一致。
